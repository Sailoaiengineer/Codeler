# Task 8 for ChatGPT: build the real Codeler app and installers

Read briefs/chatgpt.md and the review sections at the end of briefs/chatgpt-log.md (rules apply). Do task 8 only, then stop.

## Context
- `vscodium/` is a clone of VSCodium; `vscodium/vscode/` is VS Code at the pinned commit, which currently has Codeler's core changes applied **by hand** (dev build) and a hand-edited `product.json`. A real build must reproduce everything from scripts, not from that hand-edited tree.
- Codeler's changes to VS Code: `patches/codeler-core.patch` (title bar, labelled activity bar, 48px title bar, built-in extension registration). VSCodium applies every `vscodium/patches/user/*.patch` during `prepare_vscode.sh` (after its own patches).
- VSCodium build-script changes (Codeler names/ids, `.codeler` data folder, extension copy step): `patches/vscodium-build.patch`, already applied in `vscodium/` (see `git -C vscodium diff`).
- Icons: generated by `python -I brand/make_icons.py` into `vscodium/src/stable/...` (already done).
- Tools now installed: Visual Studio 2022 Build Tools (C++ + Spectre), Node 24, Python 3.13, Git Bash, 7-Zip, jq, Rust (rustup, stable). Downloads of npm packages and of whatever VSCodium's own build scripts fetch (Electron, built-in extension VSIXs, Inno Setup if its script installs it) are allowed. Anything else: write it in the log as a request and skip.

## Build
1. Make the build reproducible: copy `patches/codeler-core.patch` to `vscodium/patches/user/codeler-core.patch` (regenerate it against a clean checkout of the pinned commit if it doesn't apply cleanly after VSCodium's own patches — fix conflicts against their patched files, keep Codeler's behaviour identical). Add a small `scripts/build-windows.sh` in the Codeler repo that: regenerates icons, resets `vscodium/vscode` to a clean checkout of the pinned commit (or lets VSCodium's `get_repo.sh` do it), and runs VSCodium's `dev/build.sh` in Git Bash with the flags for a Windows x64 build **including the installer** (`-p` style packaging if supported; read `vscodium/dev/build.sh` and `docs/howto-build.md`). Keep the hand-edited dev tree from interfering (move it aside or let the script reset it; don't lose `vscodium/vscode/node_modules` if avoidable).
2. Run it. Expected output: `VSCode-win32-x64/Codeler.exe` and an installer `.exe`/`.msi` under `vscodium/assets` (names depend on VSCodium's scripts). The build takes a long time; run it in the background and poll its log.
3. Smoke test the built app: launch `Codeler.exe --user-data-dir <temp> --extensions-dir <temp>/ext <sample/project-aurora>` and confirm from its log that `codeler.codeler` activates without errors and the window title says Codeler. Close it.
4. CI for all three platforms: add `.github/workflows/build.yml` to the Codeler repo with jobs for windows-latest, macos-latest (x64 + arm64) and ubuntu-latest that check out this repo, clone VSCodium at the commit recorded in `vscodium` (record it in `scripts/vscodium-commit.txt`), apply `patches/vscodium-build.patch`, copy patches/codeler-core.patch into its patches/user, run make_icons, build, and upload the installers as artifacts. Unsigned is fine; leave clearly named placeholders for signing secrets (Apple, Windows) and say in the log what the owner must add. Don't add auto-update servers; leave `CODELER_UPDATE_URL` unset.
